# 界面语言维护

所有语言资源均随插件分发，在本机读取，不调用在线翻译服务。

- `i18n.js`：独立语言加载、插值、默认语言回退和静态界面应用。
- `locales/languages.json`：语言列表，包含 `code`、显示名 `label` 和语言包 `file`。
- `locales/zh-CN.json`：中文语言包与默认回退内容。
- `locales/en.json`：英文语言包。
- `app.js` 通过 `t(key, values)` 引用条目；HTML 使用 `data-i18n`、`data-i18n-placeholder`、`data-i18n-aria-label` 等属性。

键使用可读的英文消息作为稳定标识。翻译只修改值；保留 `{v0}`、`{v1}` 等插值名称，可调整其在句子中的顺序。字符串通过 `textContent` 或普通属性写入界面，不解释为 HTML。

## 新增语言

1. 复制 `locales/en.json` 为新文件，例如 `locales/ja.json`，翻译各条目的值，保留所有键与插值名称。
2. 在 `locales/languages.json` 增加 `{"code":"ja","label":"日本語","file":"ja.json"}`。
3. 重新加载插件并打开助手页，顶部语言菜单自动出现新增语言。不需要改扫描、下载或 ZIP 逻辑。
4. 运行项目测试，检查键与插值完整性，再检查长文案和窄窗口布局。

选择保存在 `chrome.storage.local.uiLanguage`。默认中文；未完成的翻译条目回退到中文。语言包每次打开助手页仅按需读取一次，不加入课程清单缓存。

课程名称、文件名、Module 名称、来源标题及实际下载目录都属于课程数据，不随界面语言改变。扫描器与下载引擎的诊断在显示时统一通过语言模块转换，保留底层任务状态与下载行为。

新增诊断可传 `{code: "稳定英文消息键", params: {v0: value}}` 给 `CanvasI18n.message()`，或直接传无插值消息键。旧引擎的中文诊断继续兼容。不要用课程名、文件名作为消息键，也不要在引擎中缓存已翻译文案。测试会检查静态界面引用的键是否存在、两种语言键和插值是否一致。
